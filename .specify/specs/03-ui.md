# 03 — Sidebar UI

A single webview view in a dedicated activity-bar container. Built
with plain HTML/CSS/JS — no React, no build step. Lives in
`src/ui/media/` and is served by `controlPanel.ts`.

## Activity bar

- Container ID: `agentbridge`
- Title: **AgentBridge**
- Icon: a simple SVG (bridge silhouette or arrows; chosen during
  Phase 4 polish)

## View

- View ID: `agentbridge.controlPanel`
- Title: **Control panel**
- Type: webview view (not a tree view)

## States

| State      | Pill colour | Pill text      | Button label   | Endpoint shown? |
|------------|-------------|----------------|----------------|-----------------|
| `stopped`  | grey        | Stopped        | Start server   | no              |
| `starting` | amber       | Starting…      | (disabled)     | no              |
| `running`  | green       | Running        | Stop server    | yes             |
| `stopping` | amber       | Stopping…      | (disabled)     | yes (greyed)    |
| `error`    | red         | Error: «msg»   | Start server   | no              |

The pill and button update from `state` events emitted by
`ServerController`.

## Controls

### Start / Stop button

- Primary action. Full-width.
- Calls `agentbridge.toggle` (which dispatches to `start` or `stop`
  based on current state).
- Disabled during `starting` / `stopping`.

### Endpoint

- Read-only text. Click "copy" to copy `http://127.0.0.1:<port>` to
  clipboard via `vscode.env.clipboard.writeText`.
- Hidden in `stopped` / `error` states.

### Model dropdown

- Populated on view load by calling `vscode.lm.selectChatModels()`.
- Selecting a model writes to `agentbridge.defaultModel`. This is the
  fallback for requests whose `model` field can't be resolved.
- If no models are available (Copilot extension not installed or not
  signed in), show: *"No language models available. Install GitHub
  Copilot and sign in."*

### Port input

- Number input, default 5173, range 1024–65535.
- "Apply" writes to `agentbridge.port`. Takes effect on next start.
- If the server is currently running, show a hint: *"Restart server
  to apply."*

### Recent activity

- Last 50 entries (in-memory only — cleared on extension reload).
- Each entry: timestamp, method, path, status code, duration, model
  (when applicable).
- Status >= 400 rendered in red; otherwise default colour.
- "Clear log" empties the in-memory list.

## Webview ↔ extension protocol

The webview never imports `vscode`. It communicates via `postMessage`.

### Webview → extension

```ts
type FromWebview =
  | { kind: "ready" }                     // sent on load; extension responds with full state
  | { kind: "toggle" }                    // start or stop
  | { kind: "setPort", port: number }
  | { kind: "setModel", modelId: string }
  | { kind: "copyEndpoint" }
  | { kind: "clearLog" };
```

### Extension → webview

```ts
type ToWebview =
  | { kind: "state", state: ServerState, port: number, message?: string }
  | { kind: "models", models: { id: string; label: string }[], selected: string | null }
  | { kind: "request", entry: ActivityEntry }
  | { kind: "logCleared" };
```

## Accessibility & theming

- Use VS Code CSS variables (`--vscode-editor-background`,
  `--vscode-button-background`, `--vscode-foreground`, etc.). No
  hard-coded colours.
- Buttons get `:focus-visible` outlines.
- Pill colours come from semantic VS Code variables
  (`--vscode-charts-green` and similar) so they respect the user's
  theme.

## Out of scope (for now)

- Multiple servers / multiple ports.
- Auth-token configuration UI (decision D3 — there are no tokens).
- Per-request inspection ("click an entry, see headers"). The
  OutputChannel covers this for power users.
- Settings UI for advanced behaviour. Use VS Code's settings editor
  (`agentbridge.*`) for anything not exposed in the panel.
